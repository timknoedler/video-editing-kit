# Premiere Pro: bridge notes

**Connection:** the `premiere-pro-mcp` bridge (npm package `premiere-pro-mcp`, github.com/leancoderkavy/premiere-pro-mcp), which talks to Premiere through a CEP panel (Window > Extensions > MCP Bridge). Install per its README, then verify read-only with `ping` / `verify_premiere_connection`; check both `backend: cep` and `backend: uxp` and note which answers. Build the first assembly with `scripts/xml_from_spec.py` and `import_media` the .xml.

Tested on Premiere Pro 26.5.2 with the CEP backend of the MCP bridge. Behavior can change with Premiere and bridge versions: re-test anything marked as failing before working around it, and record new findings in `~/Editing-Notes/LESSONS.md`.

**Efficiency rule:** Priority is the fastest reliable workflow. Before declaring a tool path broken, test every alternative route on a throwaway sequence (and note the test in LESSONS.md). When choosing between routes, time them on a real shot list and record the numbers in LESSONS.md.

**Unavailable through the MCP (don't try, leave a marker instead):** speed changes/ramps, reverse, nesting (on the CEP backend), styled caption creation, undo/redo, replace clip media, EDL import, opening a sequence in the Timeline panel (`set_active_sequence` doesn't — ask the editor to double-click it in the bin).

**Works well:** FCP XML import via `import_media` (whole sequences in one call, verified frame-exact; on re-import Premiere reuses existing master clips — import the XML once into a fresh project, as the first import creates its own master clips even if the media is already imported); `manage_proxies` attach + `has_proxy`; `set_clip_rotation`, `set_clip_scale`; `slip_edit`; `create_sequence_checkpoint`; `duplicate_sequence`; `rename_project_item`; `move_items_to_bin`; `create_bin`; readback tools (`get_full_sequence_info`, `get_sequence_structure`, `get_timeline_summary`, `get_effect_properties`, `get_clip_volume`); `export_sequence_clip_review_frames` (composite at each clip midpoint).

**Lumetri by script (tested 2026-10-12, a reel set, 45 clips):** `apply_effect "Lumetri Color"` then `set_effect_property` with display names `Highlights`, `Shadows`, `Temperature`, `Tint`. The first match is Basic Correction (indices 21/22/14/15), not the Creative/Color Wheels duplicates; verify once with `get_effect_properties`. FCP XML does not export Lumetri; a corrected clip shows as an effect with an empty `<name>`.

**Unreliable or needs a workaround (Premiere 26.5.2, CEP):**
- **`stabilize_clip` fails** ("empty legacy QE video effect catalog"). `apply_effect "Warp Stabilizer"` + `set_effect_property Smoothness 1` works; analysis is done when `inspect_stabilizer_status` shows AnalysisStatusCounter 408 and an "Auto-scale (x%)" label.
- **`set_work_area` is refused** on these sequences (reads back unchanged), so `export_sequence(work_area_only)` can't limit the range. To end an export at the sequence Out point, render the whole sequence and cut the tail with ffmpeg stream copy (`-c copy -frames:v N`), keeping the untrimmed file aside.
- **Re-leveling a finished file:** a plain `volume` gain plus AAC re-encode can raise true peak (one reel: -1 dB gain took TP from -0.6 to -0.4). Add a soft `alimiter` (limit ~0.73) and re-measure with ebur128.
- **`overwrite_clip` of an N-frame ProRes render lands as N-1 frames**, leaving a 1-frame sliver of the old clip. Render N+1 frames and overwrite again: it fills the slot exactly and covers the sliver, with nothing deleted.
- **Track reorganization (`move_clip_to_track`, tested 2026-10-12, a wedding film ): reliable.** 44 moves all `verified`; effects (Lumetri, Warp Stabilizer, Time Remap, Motion keyframes) travel with the clip. It refuses an occupied destination, so plan from the FCP XML first: compute the topmost visible clip per frame, remove clips that are never visible (hidden under others), trim partial overlaps, then move. Verify with an XML diff of (clip, source frame) per frame plus each clip's effect list; this caught a 1-frame gap left by a trim that ended 0.0001 s short (`set_clip_duration(end_seconds=next start)` fixed it). `rename_track` works for video and audio. During an `export_sequence` render the bridge times out on other calls; wait for the file to settle first.
- **`delete_track` fails on CEP** (26.5.2: `seq.deleteVideoTrackAt is not a function`). To get rid of empty tracks, slide every layer down with `move_clip_to_track` (bottom-up, so each destination is empty) and leave the empty tracks on top; the editor can use Sequence > Delete Tracks > All Empty Tracks. **After moves, diff the XML against the pre-move export:** `move_clip_to_track` drops transitions on the moved clip (the title's Cross Dissolve fade-in vanished; re-add with `add_transition_to_clip`, which errors on readback but applies it — check the XML), and 3 of 172 moves reported "source in/out changed": the in-point came back 0.0001 s early, which can flip the first frame. `slip_edit(+0.0001)` restores it.
- **`add_keyframe` times are media time, not clip-relative** (tested 2026-10-12, 26.5.2): `time_seconds=0` lands at the start of the source file, outside the visible clip, so the clip just holds the last key's value. Use the clip's `inPoint` (from `get_active_sequence`) for the first key and `outPoint - one frame` (scaled by (out-in)/duration for retimed clips) for the last, then check `<keyframe><when>` against the clipitem's in/out in the FCP XML. `remove_keyframe` takes the same time base. **Push-in on an off-centre subject:** set Position and Anchor Point to the same normalized point (x of the subject, y 0.5); frame 1 stays identical and the frame grows away from the subject.
- **Held frames from short source ranges (a wedding film 2026-10-13):** a clip whose source range is 1 frame shorter than its timeline slot holds its last frame; through Warp Stabilizer it plays back "squished". Find them by scanning the render for consecutive frames that barely change (mean abs diff < 0.4x the local median at 192x96; slow motion produces false hits, check by eye). Fix by starting the clip 1 frame later and extending the neighbour with `set_clip_duration` (it pulls real frames when the media has handles; verify with `export_frame` on both sides). **Always pass exact frame times** `f*1001/24000`: a value 0.00004 s off the grid makes the clip overlap or leave a 1-frame hole that only shows up in the render or XML.
- **'Vows too loud' when levels already match:** check tone, not just level. A dull, boxy lav (2-6 kHz 10-15 dB down vs the other mics) reads louder at the same loudness. Lower it 2-3 dB and the rest of the vows 1-1.5 dB, ramps inside pauses, and leave the line the editor says is right untouched.
- **When the editor ripples dialogue on the timeline, rebuild the baked stems:** the true-peak limiter was applied to voice+bed as aligned; a 0.63 s ripple of the voice (split voice clips) pushed the mix to +0.1 dBTP. Bake the ripple into the voice stem (shift + silence the hole), re-limit the affected window, re-lay all stems at 0, and confirm with an audio-only Waveform render (compare with the offline sum).
- Trimming (tested 2026-10-05 on 26.5.2): `trim_clip`, `set_item_in_out` and `set_source_in_out` fail verification. **These work:** `create_subclip` (frame-exact in/out, keeps V+A together) → `add_to_timeline`; `set_clip_duration` (moves a clip's end); `slip_edit`; `split_clip`. `set_clip_duration`/`slip_edit` act on ONE track item — do video and audio separately or they desync. Subclips pile up in the bin and CEP can't delete them.
- **Which to use:** whole first assembly → XML (`xml_from_spec.py`; one import builds every sequence with gain, punch-ins, markers; ~10 s vs ~3 connector calls × 2-3 s per shot plus separate gain/scale/marker calls). Small revisions on a live timeline (swap a shot, nudge a cut) → connector: `create_subclip` + `add_to_timeline`, `slip_edit`, `set_clip_duration` on both V and A.
- **XML mixed frame rates (tested 2026-10-05):** Premiere reads clipitem `<in>/<out>` in the sequence timebase whatever `<rate>` says; per-clip rates put 29.97/59.94 clips 1.25x/2.5x late. `xml_from_spec.py` now counts in/out at the sequence rate. Declaring audio on a silent DJI file makes it import offline; the builder now omits it.
- `set_clip_position` stores the value as given, but Position is normalized (0-1, centre 0.5,0.5): pass normalized coordinates, then verify with a review frame.
- `find_project_item_by_name` returns the first match and labels bins `type: "sequence"` (a wedding film: a bin and the film shared a name). Before `rename_project_item`, confirm with `get_project_item_info` (MediaType `Sequence`, not `Bin`) and check `rename_project_item` returns `sequenceVerified: true`.
- **Never ripple a sequence that has transitions** (tested 2026-10-05, 26.5.2, a wedding film). `add_to_timeline` inserts shift clips but leave every transition at its old time; the sequence then won't export (`export_sequence`: "did not write", even for a 40 s range). Also, the insert does **not** ripple its own target track (insert onto an empty track). **Instead:** build the new part as its own sequence, keep a clean duplicate of the original, and lay them end to end with `create_sequence_from_clips([newPart, originalCopy])` (sequences become nests; transitions/effects inside stay intact). Verify with a render.
- `create_subclip` floors **both** in- and out-points that sit a hair off the frame grid: snap to the grid and add +0.01 s (in = f/fps + 0.01, out = (f+N)/fps + 0.01), then confirm lengths (e.g. build with `create_sequence_from_clips` and read back).
- **Same floor on timeline in-points** (a wedding film, 2026-10-06): a nest placed with in 80.121708 s (frame 1921 is 80.12170833) played frame 1920. Picture floors to the frame; **audio does not** (it uses the exact time). Fix picture with `slip_edit(+0.0001)` on the video item only, and check ticks (254016000000/s; 23.976 frame = 10594584000) in the slip readback.
- **Assembly without ripple:** `overwrite_clip` the item at the target time (it overhangs and extends the sequence), `set_clip_duration(end_seconds=…)` to the next cut, then `slip_edit(+in)`. V and A separately. Frame-exact in ticks; ~3 calls per piece.
- **Trimmed nests render audio crossfades wrong** (26.5.2, tested 2026-10-06): a nested sequence placed with an in-point > 0 rendered the audio transitions *inside* it incorrectly (music up to 5 dB too loud for the length of each crossfade). The same nest untrimmed (in 0) renders exactly. Fix: render the nest's audio once to a 32-bit WAV stem from an *untrimmed* wrapper sequence and use stem slices for the audio; keep the nests for picture. Verify any nested audio against a direct render of the inner sequence.
- Exports: `work_area_only` was ignored (exported the whole sequence). The built-in WAV preset is 16-bit; a copy of `Waveform Audio 48kHz 16-bit.epr` with `ADBEAudioSampleType` = 3 gives 32-bit int (still clips at 0 dBFS, so render stems with headroom, e.g. -6 dB).
- **the editor prefers flat timelines (no nests) for anything he'll polish** (a wedding film, 2026-10-06). Nest-based assembly is fine as a working method, but deliver a flattened sequence: export FCP XML, flatten our nests (write a job-specific flattener; take segment ranges from the build layout, the XML's in/out for trimmed nests is wrong), re-import with `import_media`, then repair and verify by render. **What the Premiere XML round trip loses or breaks:** Warp Stabilizer (re-apply by exact name with `apply_effect` "Warp Stabilizer", set Smoothness; it analyses itself); speed changes (in-points drift, one 40% clip came back 39.5%, a *reversed* clip came back at 2%); position keyframe times on speed-changed clips (stretched by 1/speed); interpreted-footage speed (re-place the interpreted subclip); Motion position of clips that are nested sequences (lands at [0,0]); stereo audio written by hand as one clipitem (imports as mono, -3 dB: copy Premiere's own stereo track pair structure instead). The bridge can't set speed, reverse, add tracks or write vector (position) keyframes, so leave those few for the editor with clear clip names. Better next time: assemble flat from the start (overwrite into one sequence) and avoid nests for picture.
- **More FCP XML facts (a wedding film 4K re-target):** Basic Motion `center` is a fraction of the *media* size (x = 0.5 + h·media_w/seq_w), so 1080 proxies → 4K originals in a 4K sequence keep their values, while 4K media that sat in a 1080 sequence need scale and center doubled. Keyframe `when` on speed-changed clips is speed-scaled (multiply by speed before import), and keyframes copied out of a flattened nest need the inner clip's in-point added; even then check every keyframed clip by render (one drone's keys still landed outside the clip and held the end value). Lumetri never travels in XML. Re-pointing `pathurl` from `/Proxies/X_Proxy.mov` to `/X.MP4` (+ 3840x2160 in samplecharacteristics) puts the originals on the timeline; re-attach proxies with `manage_proxies` afterwards.
- **Blending two versions of the same dialogue (raw lav + AI-enhanced):** check the alignment at sample level before mixing. a wedding film had the lav 25 ms late (piece-wise envelope alignment with an 8-sample lag search), which made a slapback/doubling sound the editor heard as "weirder"; the enhancer also adds 0.1-0.2 ms of extra delay above 1.5 kHz (comb notch ~3.7 kHz). Verify with per-band coherence of the two layers (|a+b|² vs |a|²+|b|²: +3 dB = clean, 0 dB = smeared). Simpler and what the editor chose: keep the enhanced voice and lay real room tone from the same mic under it (next item).
- **Enhanced speech sounds like a booth → add room tone** (2026-10-06): take quiet stretches of the *same* recorder/lav as each section, stitch with ~150 ms equal-power crossfades, place it at that mic's own speech-to-floor ratio under the final voice (measured: 28-30 dB on the lavs), 0.4 s fades at the section edges, and put it on its own track so the editor can ride it. 
- **Per-clip gain:** `set_clip_volume(volume_db)` is real dB (a reel set 2026-10-07: render-verified within ±0.5 LU, one call per clip; +15 dB max). Fastest way to level bites to -19 LUFS on a live timeline; check by rendering audio only (`export_sequence` with the Waveform preset, then ffmpeg `ebur128` per bite).
- **Timeline times are k/23.976 s exactly** (ticks), not k×1001/24000: an end set from the latter sits a hair before the frame and leaves a 1-frame flash of the track below. Take boundary times from Premiere's own readback (`get_active_sequence`), not your own math.
- **Slow motion without the speed tool:** render 59.94p windows to 40% ProRes with ffmpeg (`-ss in -frames:v N -vf "setpts=2.5*(PTS-STARTPTS),scale=in_range=full:out_range=limited"` `-r 24000/1001 -c:v prores_ks -profile:v 1`), then import and place. The grade matches (render luma within 0.5%). `overwrite_clip` places these files 1 frame short, so `set_clip_duration` each to the next cut. Keep the renders on the SSD in `_edit/` (section 0).
- `overwrite_clip` can report "no verifiable new placement" when re-laying an item that's already on the track, yet still apply it; read back before retrying. Subclips cut from 59.94p media can come out 1 frame long; re-overwrite the following clip at its slot start to trim the overhang.
- **Handoff snapshot shortcut:** `export_as_fcp_xml` per sequence to `_edit/snapshots/<seq>_handoff.xml` (full structure, framing and levels in one file), plus the `[handoff]` copies. At Phase 5, run `get_sequence_structure` on the handoff copy and on the editor's final to diff, instead of hand-writing big JSON now.
- `export_frame` (QE) is a quick way to verify a single fix by image without a full render. If auto-mode blocks a timeline edit as destructive, stop, tell the editor the exact manual steps, and retry only when he asks.
- **Voice/music stems from an edited sequence** (a wedding film ): disable the voice clips (recorders/lavs), render the sequence (untrimmed wrapper, -6 dB, 32-bit WAV) = bed; voice = full mix − bed. Bit-exact (Premiere's clip mix is linear when there are no track dynamics); one render instead of two, and only one set of enable/disable calls to undo.
- **Syncing a second camera without timecode:** camera `M01.XML` CreationDate gives each clock; derive the clock offset between two cameras from one already-verified sync, predict the offset (±1 s), then refine with a speech-band log-energy cross-correlation over a 90 s window. Confirm the method reproduces a known sync first.
- **Mixing:** clip Volume tops out at **+15 dB** real. A limiter as a clip effect isn't a reliable master limiter (effect order vs the Volume ride not verified, and it only sees one clip): put the limiter on a wrapper sequence (the film nested once, untrimmed) and export that. `apply_audio_effect` works by exact name ("Amplify", "Hard Limiter") even when the catalog lists nothing. Normalized params: Amplify Left/Right and Hard Limiter Input Boost dB = 144·v − 96 (0.6667 = 0 dB); Hard Limiter Maximum Amplitude dB = 100·v − 100 (0.985 = -1.5 dB); "Limit True Peak" 1 = on. Verified by render.
- `add_keyframe` / `add_audio_keyframes` times are **source (media) time**, not clip-relative: add the clip's `inPointSeconds`. Keys left before the in-point still interpolate into the clip; remove stray keys.
- `add_audio_keyframes` `level_db` uses Premiere's internal scale: **real dB = value + 15** (pass -21 for -6 dB). `get_clip_volume` reports real dB. Verify levels from a render.
- Node IDs change when a sequence is (re)activated; re-read IDs after `set_active_sequence` and never run edits in parallel with it ("Clip not found").
- The `enabled` flag read back by `get_sequence_structure` / `get_track_info` can stay `true` after `enable_disable_clip` succeeds; confirm disabled clips by render.
- **Create the output folder before any export/XML call.** Exporting to a folder that doesn't exist opens a modal error dialog in Premiere that blocks the bridge until someone dismisses it (a wedding film: `export_as_fcp_xml` hung 120 s, bridge unreachable).
- `set_work_area` doesn't apply, and `export_sequence(work_area_only)` exported the whole sequence (2026-10-06); render the whole thing and cut the range with ffmpeg.
- Outside projects (another editor's cut) may fade the whole film with transitions on a full-length adjustment layer, and may be edited on proxy files as media (check `mediaPath` before export).
- CEP can't delete project items: rename + move to a `ZZ_discard` bin. Check a discard bin holds nothing a sequence still uses.
- `preview_edit_plan` silently accepts unknown fields, so it can't be trusted for source ranges.
- `create_sequence_from_clips` drops the whole clip in; useful only to get a sequence with matching settings.
- `import_folder` on ~150 4K clips times out and blocks the bridge for several minutes.
- `build_caption_artifact` requires a UXP transcript revision (`sha256:` hash) — unusable on CEP.
- UXP connector: unreachable in both jobs so far; verify at Phase 0 and test its trims before relying on XML for small revisions.
- **Interview re-cut on silence (2026-10-08):** the editor heard dead space and clipped words in the parent bites. Check every bite edge with word timestamps (`whisper-cli -ml 1 -sow`) *and* a 30 ms energy map of the source around each in/out; whisper's word times can be off by 0.3-0.5 s (it put "If" 0.6 s early and missed the interviewer's "go ahead"). Put ins in the silence before the first syllable and outs after the word's tail. Join adjacent bites from the same take into one continuous range when the source gap is just a natural pause. Check which camera file each bite came from (`pathurl` in the XML; one bite came from a different camera file than assumed). After re-cutting, re-enhance (stems are timeline-aligned) and re-time the b-roll so every dialogue edit is covered. Mixing a lav with its enhanced version 50/50 is safe when the stems are aligned (coherence test ~+3 dB).
- **Jello / stabilizer check (2026-10-08):** render the reel before and after Warp Stabilizer and run `scripts/jello_check.py before.mp4 after.mp4 cuts.json` (per shot: non-rigid flow left after a homography; ratio >1.5 = jello). Also compare background shake on the renders: if a shot shakes *more* after stabilizing (the stabilizer tracked the subject), set its Smoothness to 0. **Cross-reel repeats:** compare source windows, not just clip names; same-moment reuse across reels is what viewers notice (the same moment showed up in 4 of 5 reels). **Replacing a slow-mo shot mid-timeline:** a re-overwritten neighbor loses its Motion (re-apply X from the XML), and overwrite leaves 1-frame tails to remove.
- **Adobe Enhance Speech via the Adobe connector (2026-10-08):** render dialogue-only WAV from the reel (mute music/nat; create the export folder first), trim to reel length, upload (`asset_initialize_file_upload` → curl PUT → `asset_finalize_file_upload`), `media_enhance_speech` → 3 stems (speech mono, background, reverb), downloaded via their presigned URLs. Stems come back sample-aligned. Mix speech + background (as is) + reverb at -12 dB, normalise to -19 LUFS, place on a free track at 0, mute the original dialogue track (keep it). The bridge can't add tracks, so pre-mix into one file and keep the stems in `_edit/work/enhance/` for the editor to ride. Ask the editor before sending client audio to Adobe. With two jobs at once, the progress widget only surfaced one result; resubmitting the other gave a fresh widget.
- **`add_audio_keyframes` quirks (2026-10-08):** keyframe times are **source-media time** (add the clip's in-point), and `level_db` is written as a raw linear amplitude, which is 15 dB louder than Premiere's dB scale (Premiere stores 0 dB as 0.1778). So to get D dB at clip time t, pass `time_seconds = in + t` and `level_db = D - 15`. Read back with `get_keyframes` (value = 10^((D-15)/20)) and render-check. The first try put every keyframe before the clip's in-point and the music played at -45 dB.
- **Warp Stabilizer via bridge (one reel):** `apply_effect "Warp Stabilizer"` then `set_effect_property Smoothness` works on 4K clips in the 2160x3840 sequence. It does nothing on a clip with a speed change (Time Remap), and `remove_effect_by_name` fails on CEP, so check speed before applying. **Analysis does not always start:** if you switch the active sequence (or export) right after applying, some clips stay on "Click Analyze to begin" (`AnalysisStatusCounter` 201) and render with a blue banner. The bridge cannot press Analyze, and changing Method does not trigger it. Verify by rendering and scanning one mid-shot frame per clip for the banner (pure blue rows, BGR ~237,40,0). Fix: re-render the shot as an exact-length ProRes clip, overwrite it into the slot, re-set Motion, apply WS again, then keep that sequence active until it finishes. An "Auto-scale" label with no % does not mean unanalyzed; trust the render. **Overwrite and length:** overwrite a clip rendered at exactly the slot length so nothing spills into the next shot. Premiere sometimes reads it 1 frame short; `set_clip_duration` extends it by that frame.
- **Recutting an interview for breathing room (2026-10-09):** the editor heard the speaker's lines as "cut short" and "stepped on". The cause was bites butted with ~0.3 s between them, a VO that clipped a key word, a head that started mid-word, and a dropped last phrase. Map every edge with whisper word times plus a 30 ms energy map of the source ±3 s, aim for ~0.6 s from the last word's tail to the next word, and split a bite under b-roll to shorten a long internal pause. `create_subclip` placed every in-point 1 frame early; check the in-points after placing and mute or fade the first frame when it catches the previous word's tail. Re-enhance the new dialogue (stems are timeline-aligned). Until the enhanced stems are back, put a level-matched lav-only temp voice on the timeline.
- **Final QC pass before delivery (a reel set, 2026-10-12):** render every reel and check automatically: loudness/true peak (`ebur128=peak=true`), `blackdetect`, `freezedetect`, scene cuts for shots under 0.3 s, a per-frame luma scan for single black frames, and the Warp Stabilizer banner. Found: (1) adjustment layers longer than the content left 6-8 s of black at the end of three reels; trim them to the last clip. (2) Music hard-cut at the end (still -17 to -32 dB on the last frame); add a ~1 s fade with keyframes. (3) the editor's clip-gain changes (Audio Gain, visible only as a "Gain" filter in the FCP XML) pushed one reel to -11 LUFS and +0.2 dBTP; scale voice and music together to keep his balance. (4) One reel always rendered its final frame black through the bridge, even with matching clip ends; set the sequence In/Out one frame short and tell the editor to export with Sequence In/Out. Also look at the rendered contact sheet for the same kid in consecutive shots.
- **Reframing a wide for 9:16:** a 16:9 wide holds three possible 9:16 crops; check each against the neighbouring shots for repeated people before picking. Position X maps to crop centre as cx = 0.5 + (0.5 - X) * 0.3164 at scale 177.78 (X 0.1 shows the right third). Simulate punch-ins with ffmpeg crops first: visible source = 2160/(S/100) x 3840/(S/100) px, and a position_y below 0.5 shows lower in the frame.
- **Social pacing for interview reels (a reel set, 2026-10-12):** the first cut should land within about 2.5-3 s; the editor approved cutting away from a 6 s on-camera opener. When the speaker lists things ("fun, dynamic, and interactive"), give each word its own quick b-roll shot, cut on the energy dips between words (0.7-1.2 s shots read fine). Keep the speaker on camera for the first 1-2 s so viewers know who is talking. Montage reels on a 3-beat grid (1.2-1.5 s shots) are already fast enough.
- **Interview reels go to -14 LUFS too (2026-10-08):** the editor heard the -19 LUFS interview reels as "quiet across the board" next to the -14 montage reels. Deliver every reel in a set at about -14 LUFS integrated with true peak at or below -1 dBTP. Voice: +5 dB and `alimiter=limit=0.79:attack=3:release=60:level=disabled` on the enhanced mix, then raise music keyframes or volume +5 dB to keep the bed ratio. Measured -14.0 to -14.3 LUFS, peaks -0.9 to -1.1. overwrite_clip on V2 shortens the next clip's head, and `trim_clip` can't extend it back on Premiere 26 (the bridge no-ops), so extend the new clip to meet the neighbour instead.
- **Interview music bed (2026-10-08):** song at about -20 dB under -19 LUFS dialogue gives a bed near -34 LUFS (≈15 dB under), measured by rendering with and without the bed and differencing. Check the mix peak (it went from -0.6 to -0.1 dBFS) and flag it for the master limiter. Pick the song section so its last note lands over the final shot. When stretching a shot for a longer beat slot, re-run `bg_shake.py` on the new length (one reel's opener went from 0.88% to 1.5% at 2.4 s; the finale's tail had a 6.8% bump), and shift the in-point earlier rather than the out later.
- **Beat-grid montage (2026-10-07):** get BPM, phase and downbeats from the song file (librosa or `detect_beats`), pick a music section that starts on a downbeat and ends on a phrase button plus ring-out, then plan cut frames as `round((n*beats*60/BPM)/(1001/24000))` (3 beats at 135 BPM = 32 frames). Place picture with `overwrite_clip`, then `set_clip_duration` each clip to its slot (it extends past a subclip's out). Cut the music as a subclip at the section's start and overwrite it to A-music. Verify with an audio-only Waveform render: onsets at each cut within 1 frame (got 1–25 ms) and loudness -14 LUFS for social. FCP XML clamps `out` to the subclip's media length, so true source out = in + (end − start).
- **Shake: use `scripts/bg_shake.py` as the tie-breaker (2026-10-07).** whole-frame shake scores over-flags wide shots with lots of crowd motion (a crowd wide scored 2%), and `action_scan.py` jitter over-flags close-ups where hands fill the frame (5–10 px on steady shots). `bg_shake.py` tracks only the outer border ring (RANSAC, 1 s smoothing) and matched the editor's eye: the 5 shots he called shaky were the only ones above ~0.85%. Measure the exact timeline window (in + slot length); a +0.5 s tail produced a false flag. Also check vertical crops before choosing a "whole group" wide: at Scale 177.78 a 9:16 frame shows only ~32% of the 16:9 width, so wide circle shots read as empty floor.
